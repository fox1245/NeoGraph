# "The Beast" — 코드 검토 및 학문적 포지셔닝


`the-beast/` 요리책(6개 프로그램, ~1.6k LOC)에 대한 통합 검토
학문적 포지셔닝. 이 리뷰는 4명의 독립 에이전트에 의해 작성되었습니다.
병렬로 실행 — 소스에 대한 코드 검토자(Opus) 1명, 소스에 대한 코드 검토자 3명
arXiv/Scholar MCP 검색을 사용하는 문헌 스카우트 — 그런 다음 여기에서 조정됩니다. 모든
아래 arXiv id는 검색 중에 스카우트에 의해 추상 검증되었습니다.

요리책은 변형별로 자체 작성 에이전트 시스템으로 구축됩니다.

|프로그램|그것이 보여주는 것|
|---|---|
|`the_beast.cpp`|DSL, `evolve()`에서 토폴로지를 생성하고 체크포인터를 통해 롤백합니다. 오프라인, 결정적.|
|`the_beast_live.cpp`|LLM가 하네스를 작성합니다. 세 개의 게이트가 이를 검증합니다. 진단은 자가 복구 루프를 구동합니다.|
|`the_beast_apex.cpp`|모델은 ReAct 도구 호출 에이전트를 작성합니다. 도구를 바인딩하여 실행하고 자동으로 호출합니다.|
|`the_beast_forge.cpp`|MCP를 통해 도구를 검색합니다. 하나가 누락되면 LLM는 **Python MCP 서버를 작성**하고 실행한 후 다시 검색합니다.|
|`the_beast_script.cpp`|`script_node`는 게이트+런타임 효과 계약에 따라 자체 `goto` 흐름을 제어하는 ​​LLM로 작성된 Python을 실행하며 선택적으로 Google Sandbox2에 의해 격리됩니다.|
|`the_beast_evolve.cpp`|밈 루프: 다윈 토폴로지 돌연변이 + **실제 실행 적합성** + 유전 가능한 씨앗으로 주입된 라마르크식 LLM 개선.|

## 1부 - 코드 검토

**평결: 요리책으로 배송하기에 적합합니다.** 기본적으로 CRITICAL/HIGH 결함이 없습니다.
짓다. 하나의 HIGH가 *선택적* `BEAST_SANDBOX2` 경로에 있었고 이제 수정되었습니다.
로드 베어링 주장 - "컴파일러는 실행되기 전에 일관성을 입증합니다."
3게이트 + 자체 복구 루프, 체크포인트 롤백 인덱싱 및 yyjson
Footgun 회피 - 모두 검사를 받고 있습니다.

### 버그가 아닌 것으로 확인됨

**yyjson 반복자 풋건**(`x.value("k",d).begin()`는 두 번째
`.value("k",d).end()` → *다른* 임시 항목으로의 반복자 → 무한 루프)
6개 파일 모두에서 검색되었습니다. **남은 인스턴스가 없습니다.** 검토자
`operator[]`가 문서 공유 핸들을 반환하는지 확인했습니다(두 반복자 모두
동일한 상위)이므로 `x["k"].begin()/.end()`는 안전합니다. `.value()` 딥 카피만,
그리고 그것들은 이미 `the_beast_script.cpp`의 로컬에 바인딩되어 있었습니다. 이것은
한때 "공급자 중단"으로 가장했던 버그 클래스가 이제 종료된 것으로 확인되었습니다.

### 남은 권장사항(아직 완료되지 않음)

1. **`beast_common.h` 추출** — `Verdict`, `forge_gate`, `extract_json`,
`BeastNode`/`register_beast_node`는 여러 파일에 복사하여 붙여넣었으며
이미 표류했습니다(`forge` 대 `forge_gate`; 두 가지 다른 `BeastNode` 효과
계약). 중복을 제거하거나 최소한 조정합니다.
2. **`apex`/`forge`에 대한 `--selftest`** — 가장 새로운 동작(도구 바인딩,
`own_tools` 수명, MCP 하위 프로세스 수확, 위조 재발견)은
라이브 전용이므로 CI에서 확인되지 않습니다. 고정 하네스 오프라인 경로를 추가하세요.
3. **`-DNEOGRAPH_BEAST_SANDBOX=ON`를 사용한 컴파일 전용 CI 작업** 따라서 샌드박스는
경로는 발견 항목-1 UB로 다시 썩을 수 없습니다.
4. **`forge` 상대 경로** — 스톡 MCP 서버 경로는 CWD 상대 경로입니다. 해결하다
실행 파일이나 문서 "repo 루트에서 실행"에 대해.
5. **팬아웃 시 `evolve` 결정성** — 엔진이 적용되는지 확인
동일한 슈퍼 단계는 결정적인 순서로 `overwrite` 채널에 씁니다. 또는
다윈주의 검색을 유지하기 위해 `acc` 단일 작성자를 유지하도록 돌연변이를 제한합니다.
재생할 수 있는.

## 2부 - 학문적 포지셔닝

세 명의 스카우트가 같은 사진에 모였습니다. **재료는 모두 근거가 있습니다.
그리고 인용 가능; 특정 조합은 실제로 비어있는 공백입니다.** 이
"최초의 LLM 설계 에이전트"(잘 사용된)는 아닙니다. — *정확한-
거부*, 번역 검증, 밈적으로 진화된 에이전트-토폴로지 시스템.

### 참신함, 순위(가장 방어하기 쉬운 것부터)

1. **LLM가 작성한 *및* 진화된 에이전트에 대한 일관성 *oracle*로서의 컴파일러
토폴로지.** 단일 문서가 적용되지 않습니다(사용된 키 회계 + 번역).
유효성 검사 + 그래프 일관성의 형식화된 정적 분석: 매달린 가장자리, 데드
장벽, 도달할 수 없는 노드, 불완전한 경로 맵, 채널 효과
위반)을 generated/evolved 에이전트 그래프의 *전체 정확성 게이트*로 표시합니다.
특히 **번역 검증** (`compile(x).to_json() ==
canon(x)`)가 *agent-harness* 컴파일러에 적용된 것은 전례 없는 것으로 보입니다.
에이전트 생성 작업이 없는 Pnueli/CompCert 분야 직접 가져오기
사용합니다. 이것이 가장 강력한 단일 프레이밍 포인트입니다.
2. **작성자 → 새 MCP 서버 생성 → MCP**(`forge`)를 통해 다시 검색합니다.
도구-*검색* 작업은 고정 카탈로그(MCP-Zero `2506.01056`, ScaleMCP)를 사용합니다.
`2505.06416`); 도구-*생성* 작업 작성자 도구 진행 중(CREATOR
`2305.14318`, CRAFT `2309.17428`, 툴메이커 `2502.11705`, ToolLibGen
`2510.07768`). 전체 작성자-생성-재발견 루프를 찾을 수 없습니다.
*프로토콜 자체를 통해*.
3. **명시적인 Darwinian/Lamarckian 정신자 분할** — *순수한*-다윈주의적 무작위-
돌연변이 층은 Lamarckian LLM 개선과 구조적으로 분리되어 유지됩니다.
획득한 용액을 유전 가능한 씨앗으로 주입하는 층입니다.
Whitley (1994) Lamarckian-vs-Darwinian 언어. 이 분야는 거의 보편적으로
LLM를 *변이 연산자로* 사용하여 둘을 축소합니다. 리에보
(`2402.01145`)가 가장 가깝습니다("언어적 그라디언트"는 기능적으로 Lamarckian입니다).
그러나 결코 그런 식으로 틀을 잡지 않으며 순수한 다윈주의적 통제를 유지하지 않습니다.
4. **수리 신호로 진단 입력**(Reflexion의 산문 반영과 비교)
`2303.11366` / GEPA `2507.19457`) 및 **`script_node` = CodeAct
(`2402.01030`) + 게이트 및 런타임 적용 효과 계약**(CodeAct 실행
노드별 계약이 없는 임의 코드).

### 리뷰어가 요구하는 약점(출판 가능으로 가는 관문)

1. 유효성 검사기/효과 시스템에 대한 **공식적인 의미 체계 또는 건전성 증명**은 없습니다.
"Corright by construction"은 DSL가 의미를 가질 때까지의 슬로건입니다.
분석기에는 건전성 정리가 있습니다(거부 ⟹ 실제로 일관되지 않음, 수락 ⟹ 아니요
런타임에 이러한 오류가 발생함). 번역 검증으로 *하나의* 속성을 증명합니다.
(컴파일은 이 아티팩트를 다시 연결하지 않았습니다) *신원만*(표준-
의미론이 아닌 구문론). **우선순위가 가장 높은 플래그.**
2. **evolution 피트니스 작업은 장난감**입니다(산술 파이프라인). 하나 이상이 필요합니다.
실제 에이전트 벤치마크(GSM8K/HotpotQA/MBPP/GAIA/SWE-bench-class).
3. **일관성 ≠ 정확성.** 게이트는 *구조적* 일관성이 필요하다는 것을 증명합니다.
하지만 충분하지 않습니다. precision/recall(일관적이지만 작업 실패율)는 다음과 같습니다.
측정되지 않음 — "진화에 대한 적합성" 프레이밍에 치명적입니다.
4. **기준선/절제 없음.** 필수: vs MermaidFlow / ADAS / AFlow; 그리고
검사당 절제(소비된 키/TV/정적 분석기 켜기-끄기, 입력 대
산문 진단; LLM-연산자 단일 루프 대 분할).
5. **라마르키안 레이어가 사소하게 지배적일 수 있습니다.** 하위 문제가 다음과 같은 경우
일회성 해결이 가능하므로 진화적 발판은 불필요합니다. 작업을 선택해야 합니다.
블라인드 다윈주의 *및* 원샷 LLM가 모두 실패하는 *이너* 싱글샷 LLM
하지만 밈적 조합은 성공하고 **Baldwinian 컨트롤**을 실행합니다.
(정제하되 상속하지 않음; Whitley는 Lamarckian을 능가하는 경우를 예측합니다).
6. **통계적 엄격함**(≥10~30개의 시드, 효과 크기, 비모수적 테스트) 및
**비용 계산** (LLM 호출당 적합성; 밈은 *동일하게 지배해야 함)
계산*, 동일한 세대가 아님). 붕괴를 배제하기 위한 다양성 측정항목
("변이 없는 돌연변이").
7. **샌드박스 깊이.** seccomp 필터링 없음, 기능 중재(CapSeal) 없음, 없음
적대적 탈출 평가(SandboxEscapeBench), 위협 모델 없음
자체 제작된 악성 MCP 도구입니다.

### 활용할 수 있는 기초

1. 검증된 컴파일러 계보(CompCert, Pnueli TV)로 게이트 프레임을 구성합니다.
