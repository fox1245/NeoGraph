# “The Beast”——代码审查和学术定位

**Languages:** [English](RESEARCH_AND_REVIEW.md) | [한국어](RESEARCH_AND_REVIEW.ko.md) | [日本語](RESEARCH_AND_REVIEW.ja.md) | [简体中文](RESEARCH_AND_REVIEW.zh-CN.md)

对`the-beast/`cookbook的综合审查（6个程序，〜1.6k LOC）加上
其学术定位。该评论由四位独立代理撰写
并行——一名代码审查员（Opus）负责源代码审查，三名
使用 arXiv/Scholar MCP 搜索进行文献侦察——然后在此处进行协调。每个
下面的 arXiv id 在搜索过程中由调研代理进行了摘要验证。

该cookbook逐变体地构建了一个自创作代理系统：

|节目|它展示了什么 |
|---|---|
| `the_beast.cpp`|在strict Core JSON中生成拓扑，`evolve()`它，通过检查点机制回滚。离线，确定性。 |
| `the_beast_live.cpp`|LLM撰写了执行框架； 三道门控验证；诊断驱动自我修复循环。 |
| `the_beast_apex.cpp`|模型编写了一个ReAct工具调用代理；它与绑定的工具一起运行并自主调用它们。 |
| `the_beast_forge.cpp`|通过 MCP 发现工具；当缺少一个时，LLM **编写一个 Python MCP 服务器**，启动它，然后重新发现它。 |
| `the_beast_script.cpp`| `script_node`运行LLM编写的Python，控制自己的`goto`流，在门+运行时效果契约下，可选地通过Google Sandbox2隔离。 |
| `the_beast_evolve.cpp` |模因循环：达尔文拓扑突变 + **真正的执行框架适应性** + 拉马克 LLM 细化作为可遗传种子注入。 |

### 已验证无错误

**yyjson 迭代器 footgun** （`x.value("k",d).begin()` 与第二个配对
`.value("k",d).end()` → 迭代器进入*不同的*临时变量 → 无限循环）
已在所有六个档案中被追捕。 **没有剩余实例。** 审阅者
确认`operator[]`返回文档共享句柄（两个迭代器都携带
同一个父母），所以`x["k"].begin()/.end()`是安全的；仅`.value()`深层副本，
这些已经与`the_beast_script.cpp`中的当地人绑定。这是
曾经伪装成“provider 挂起”的一类错误 - 现在已确认已关闭。

## 第 2 部分 — 学术定位

三个侦察兵汇聚在同一张图上：**组成部分都有依据
并可引用；具体的组合是一个真正的、未被充分利用的差距。**这
不是“第一个由LLM设计的代理”（广为人知）——它是一个*正确的-
拒绝*，翻译验证，模因进化的代理拓扑系统。

### 新颖性，排名（最有说服力的第一）

1. **编译器作为 LLM 创作的*和*进化代理的一致性*oracle*
   ** 不适用单篇论文（已消费键计费 + 翻译
   验证+图形一致性的类型化静态分析：悬垂边、死角
   障碍、无法到达的节点、不完整的路由表、通道效应
   违规）作为生成/进化代理图上的*完全正确性门*。
   特别是，应用于*agent-执行框架*编译器的**翻译验证**（`compile(x).to_json() ==
   canon(x)`）似乎是前所未有的——
   直接导入 Pnueli/CompCert 规则，无需代理生成工作
   用途。这是最强的单一取景点。
2. **作者 → 生成一个新的 MCP 服务器 → 通过 MCP** 重新发现它（`forge`）。
   工具-*发现*工作使用固定目录（MCP-Zero `2506.01056`、ScaleMCP
   `2505.06416`)；工具-*创作*作品作者正在使用的工具（CREATOR
   `2305.14318`、工艺`2309.17428`、ToolMaker `2502.11705`、ToolLibGen
   `2510.07768`)。完整的作者-生成-重新发现循环没有找到任何内容
   *通过协议本身*。
3. **明确的达尔文/拉马克模因分裂** - *纯粹的*-达尔文随机-
   突变层在架构上与拉马克LLM细化保持分离
   将获得的解决方案作为可遗传种子注入的层，框架在
   Whitley (1994) 拉马克语言与达尔文语言。该领域几乎普遍
   使用 LLM *作为*变异算子，将两者折叠起来。雷埃沃
   (`2402.01145`) 最接近（其“语言梯度”在功能上是拉马克）
   但决不以这种方式构建它，也不保留纯粹的达尔文主义控制。
4. **键入诊断作为修复信号**（与 Reflexion 中的散文反射相比）
   `2303.11366` / GEPA `2507.19457`)，以及 **`script_node` = CodeAct
   (`2402.01030`) + 门控和运行时强制效果契约**（CodeAct 运行
   没有每个节点合约的任意代码）。

### 最近的邻居（引用这些；对比，不要声称领先）

- **一致性/验证门控生成：** MermaidFlow `2505.22967`
  （将进化搜索限制在静态可验证的工作流程空间 -

- **不断发展的代理工作流程/图：** AFlow `2410.10762`（最近的基材：

### 审稿人要求的弱点（可发表的大门）

1. **验证器/效果系统没有正式的语义或健全性证明**。
   “通过构造纠正”是一个口号，直到 strict Core JSON 有了语义并且
   分析器有一个健全性定理（拒绝 ⟹ 真正不连贯；接受 ⟹ 不
   运行时出现此类错误）。 翻译验证证明*一个*财产
   （编译没有重新连接这个产物）并且是*仅身份*（规范-
   语法上的，而不是语义上的）。 **最HIGH优先级标志。**
2. **进化适应度任务是一个玩具**（算术管道）。至少需要一个
   真正的代理基准（GSM8K/HotpotQA/MBPP/GAIA/SWE-bench-class）。
3. **连贯性≠正确性。** 门证明了*结构*连贯性，必要的
   但还不够。其精确度/召回率（一致但任务失败率）为
   无法测量——对于“进化的适应度函数”框架来说是致命的。
4. **无基线/消融。** 必需：与 MermaidFlow / ADAS / AFlow 相比；和
   每次检查消融（消耗键/电视/静态分析仪开关；键入与
   散文诊断； LLM 作为运算符单循环与拆分）。
5. **拉马克层可能微不足道地占主导地位。** 如果子问题是
   一次性解决，进化支架是不必要的。必须选择一个任务
   *超越*单次LLM，其中盲达尔文*和*单次LLM都失败
   但模因组合成功了——并运行**鲍德温式控制**
   （精炼但不继承；惠特利预测它会击败拉马克）。
6. **统计严谨性**（≥10–30 个种子、效应大小、非参数检验）和
   **成本会计**（每个LLM呼叫的适合度；模因必须在*平等中占主导地位
   计算*，不等于世代）。排除崩溃的多样性指标
   （“没有变异的突变”）。
7. **沙箱深度。** 无 seccomp 过滤，无能力中介 (CapSeal)，无
   对抗性逃逸评估 (SandboxEscapeBench)，无威胁模型
   自编恶意MCP工具。

### 可以利用的基础

1. 使用经过验证的编译器谱系（CompCert、Pnueli TV）构建门；
   将 MermaidFlow / Lean4Agent 定位为您扩展的代理端化身。
2. 赋予strict Core JSON小步语义并证明效果系统健全
   （进度+效果格的保留）——最HIGH杠杆
   学术升级。
3. 约束解码（SynCode / Outlines / CRANE）以从
   “在门口拒绝”到“无效的执行框架是无法代表的”——以及强大的
   基线（受限解码与拒绝和修复）。
4.岛屿模型/MAP-Elites（FunSearch、CodeEvolve、QDAIF）停止注入
   拉马克精英免受多样性崩溃的影响。
5. GEPA 的帕累托前沿反射环，运行*类型化*诊断。
6. **根据每个节点声明的效果契约合成的 Seccomp 策略**，加上
   基于能力的中介 (CapSeal) — 缩小了沙箱深度差距，是一种
   本身就是干净的贡献。

## 选择下一步：(c) 效果合约 → seccomp 策略综合

在三个候选后续中 - (a) 形式语义 + 健全性草图，
(b)真实代理基准+鲍德温控制，(c)效果契约→seccomp
政策——本次审查按照 **(c)** 进行，因为它：

- **解决了两位审阅者独立标记的弱点** - 代码审查的
  发现 5（“没有系统调用过滤”）和学术弱点 7（“宽容”）
  系统调用策略；没有 seccomp");
- **是确定性可验证的**（负面测试：系统调用之外
  派生的配置文件被拒绝；合法脚本仍然运行）——在“证明
  它实际上隔离了这个项目所坚持的精神，而不是（b）的精神
  LLM循环结果不确定的风险；
- **是一个独立的新颖贡献** - 报告 C 称为“seccomp 政策
  每个节点从其声明的效果契约中自动导出”一项干净的研究
  贡献，并将 strict Core JSON 的效果系统与内核级执行联系起来，
  连接系统已有的两个东西；
- **直接建立在刚刚发货的基础上**（效果契约+
  Sandbox2 路径），因此它加深而不是蔓延。

(a) 是最HIGH的*学术*优先级，但理论/写作的“草图”形式
抵抗清晰的验证； (b) 是最需要经验但也是最HIGH的-
干净着陆的风险。 (c) 是现在最好的构建和验证切片； (一)和(二)
仍然是按顺序进行的后续行动。

**状态：(c) 实施并验证。** `script_node` 现在的效果契约
带有可选的`caps`列表； Sandbox2 政策是从中“合成”的 —
缺乏 `"net"` 能力 seccomp-blocks `socket`/`connect`/…，
缺少`"exec"`块`execve`。通过负面测试验证（相同的Python，
相同的沙箱，仅声明的上限不同）：`caps=[]` →
`{"socket":"SOCKET_BLOCKED:EPERM"}`（系统调用本身被拒绝）；
`caps=["net"]`→`{"socket":"SOCKET_CREATED"}`。代码审查结果到此结束 5
学术弱点 7 是合约衍生（非手写）的 seccomp 层。
剩余沙箱深度（每个节点系统调用白名单、基于功能的秘密
CapSeal 的调解（一种对抗性逃逸评估）仍保留在路由表上。

**状态：(a) 第一期实证落地。** 纯粹的“形式语义+
健全性证明”是理论，但其*可测试的核心*——健全性/精确性-
回忆一致性门控（弱点 1 和 3）——现在是一个可运行的执行框架，
[`the_beast_gate_eval.cpp`](the_beast_gate_eval.cpp)：带标签的拓扑语料库
运行验证器（预测）和引擎（真实情况），交叉
检查，`exit 0` 当且仅当每个判决都匹配执行（当前 4/4 — E4/E3
错误⇒真正的运行时错误；连贯图和 E7 警告图
运行干净）。它测量定理 `validator-error ⟹ runtime-fault` 而不是
断言它，并且是 CI 可控制的。 *正式的*语义+书面的健全性
效果格的证明以及更大的统计数据集仍然存在
更深入的后续。 (b) — 真正的代理基准 + 鲍德温控制 — 是
接下来。

**状态：(a) 扩展——统计驱动的语料库已登陆，诚实地说
** [`the_beast_gate_fuzz.cpp`](the_beast_gate_fuzz.cpp) 缩放gate_eval
从 5 个手工标记的案例到数千个模糊的案例 - 但“没有”陷阱
打印出令人怀疑的完美精确度/召回率。诚实的观察是
引擎在编译时重新运行验证器并抛出任何错误，因此
“validator-error ⟹engine-faults”通过构造是正确的； 1.0 混乱
矩阵之外就是剧院。所以程序测量两个信息层
相反： **第 1 层** — 超过 2000 个结构突变体、编译器门和
引擎永远不会不同意（规模*回归*保证，而不是健全性
发现）； **第 2 层** — 门信任效果契约，因此节点
*谎言*（声明`writes:["out"]`但写了一个未声明的通道）航行过去
静态门 500/500 和运行时 `GraphState` 防护装置支持它 500/500。
可交付成果是*精确*的保证声明——**相对于
诚实的合约，为不诚实的合约提供运行时保障**——每一层
CI 强制执行。

**状态：(a) 完成 — 正式证明已落地。** [`SOUNDNESS.md`](SOUNDNESS.md)
提供最后一块：执行框架执行的小步操作语义
（超级步骤越过声明的通道状态，写保护是唯一的
错误规则），效果格`(𝒫(Chan), ⊆)`门原因结束，以及
门读作良构性判断`⊢ G ok`，其前提正是
错误系列 E3/E4-write/E8/E10。通过该模型，它证明了**进步/
非过失**（Thm 6.3）：在合同范围内的过门图和
