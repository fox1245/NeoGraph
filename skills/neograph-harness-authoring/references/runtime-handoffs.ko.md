# 런타임 자식 합성과 교체

**Languages:** [English](runtime-handoffs.md) | [한국어](runtime-handoffs.ko.md) | [日本語](runtime-handoffs.ja.md) | [简体中文](runtime-handoffs.zh-CN.md)

이 참고 문서는 아래 서비스를 실제로 제공하는 호스트를 위한 것입니다.
스킬이 ng.compile, ng.replace 또는 상상한 MCP 교체 도구를 API로 만들어 주지는
않습니다. 호환성 Harness MCP 인터페이스는 워크플로를 컴파일하고 시작합니다.
실행 중 교체에는 여기서 설명하는 네이티브 호스트 통합이 필요합니다.

## 필요한 호스트 정보 패킷

제공된 호스트 서비스에서 유효한 소유자/실행/버전, 현재 계보 헤드, 사용 가능한
레지스트리, 제안 스키마(템플릿 매개변수 또는 전체 소스), 입력/출력 계약,
남은 한도, 결과/진단 형식을 확보하세요. 요청에 아직 없다면 사용 가능한 설정을
살펴보세요. 바인딩을 추측하거나 작업이 실행되었다고 주장하지 말고,
어떤 계약이 누락되었는지 밝히세요.

모델은 소스나 매개변수를 제안합니다. 호스트는 권한을 제공하고 원자적 상태
변경을 수행합니다. 공급자 자격 증명과 신뢰된 권한 부여는 호스트가 보관합니다.

## 자식 생성

1. 구체적인 자식 작업과 필요한 출력에 맞는 소스 또는 템플릿 매개변수를
   제안하세요. 부모에게 허용된 기능과 남은 한도 안에서만 요청하세요.
2. 필요한 경계에서 호스트의 제안 봉투를 제출하세요. 호스트가 실제 부모/헤드를
   바인딩하고, 자원을 예약하고, 컴파일하고, 의미를 검증하고, 승인하고,
   게시하고, 자식을 바인딩합니다. 모델이 제공한 권한 부여는 권한이 아닙니다.
3. 결과를 읽으세요. 거부되면 반환된 진단과 남은 수정 허용량을 사용하세요.
   바인딩된 결과라면 정확한 자식 바인딩과 입력 계약을 사용하세요.
4. 승인된 spawn 명령을 yield하고, 결과가 필요하면 await로 감싸세요.
   자식 결과나 정확한 실패를 기록하세요. 대기열에 들어간 제안을 실행된
   자식으로 보고하지 마세요.

예를 들어 챗봇의 검토된 review 템플릿은 kind="review", turn, source를 담은
체크포인트를 내보냅니다. 호스트는 이름을 "review-" + turn으로 만들고,
바인딩 전에 검토된 템플릿과 소스를 대조하여 검증합니다. 이 필드 이름은
해당 예제에만 적용되며 범용 제안 스키마가 아닙니다.

## 현재 Harness 교체

1. 후속 실행에 필요한 내용을 명시적인 직렬화 가능 상태로 구성하세요.
   대화/작업 진행 상황과 유지된 작업에 다시 합류하는 데 필요한 정확한 입력을 담으세요.
2. checkpoint(state, stableSite)를 yield하세요. 호스트가 해당 경계에서 리스를 유지합니다.
3. 호스트가 합성 의도를 영속적으로 기록하고, 동적 컴파일을 예약하고,
   후속 실행을 컴파일/검증/승인한 뒤, 세대 CAS로 교체할 정확한 버전을 선택합니다.
4. 후속 실행은 새 제너레이터를 시작합니다. 새 작업을 수행하기 전에
   input.handoff에서 선언된 인계 상태를 복원하세요. 인계가 있으면
   카운터/이력을 처음부터 초기화하지 마세요. 호스트는 previous_run_id도 바인딩합니다.
5. 논리적 부모, 자식 관계, 출력 계약, 부여된 권한을 호환되게 유지하세요.
   남은 비갱신 자원은 후속 실행으로 이전됩니다.

경계를 넘는 것은 JSON 상태입니다. QuickJS 힙, 제너레이터 스택, 포인터,
프로미스 또는 네이티브 핸들은 넘어가지 않습니다. 게시된 그래프/버전은 불변입니다.

## 유지된 자식과 복구

유지된 자식의 바인딩과 원래 입력이 기존 작업을 식별합니다. 현재 네이티브
런타임에서는 상속된 바인딩을 기록된 입력으로 spawn하면 그 자식에 다시 합류합니다.
입력은 원래 텍스트의 키 순서가 아니라 정규화된 JSON 내용으로 비교합니다.
그 내용을 바꾸면 충돌입니다. 새 작업에는 호스트가 승인한 새 바인딩과
새로 예약된, 축소된 자식 예산이 필요합니다. 교체 과정에서 완료된 외부
작업을 반복하거나 이미 소모한 한도를 복원해서는 안 됩니다.

오래된 헤드 충돌이 발생하면 활성 세대를 다시 불러오세요. 공급자나 컴파일러의
결과가 불확실하면 제공된 호스트 경로를 통해 대조·조정해야 합니다.
사용할 수 있는 답변이 없다는 이유만으로 다시 디스패치하지 마세요.
자식에서 부모로 전파되는 취소나 전역 취소를 가정하지 말고, 호스트가 반환한
논리적 실행 계열의 취소 계약을 따르세요. 반환된 실행 보장을 정확히 보고하세요.

## 네이티브 호스트 구현 진입점

- RuntimeConfig::checkpoint_handler: 핸들/리스를 대기열에 넣고 즉시 반환하세요.
  리스를 유지하면 해당 세대가 일시 정지합니다. 호스트 작업은 스케줄러 밖에서 수행하세요.
- ProgramRuntime::prepare_child_synthesis: 제안과 호스트가 별도로 발급한
  권한 부여를 보유 중인 부모 체크포인트에 바인딩합니다. 이 권한 부여가
  부모의 남은 컴파일 예산이나 실제 경과 시간 예산을 보충하지는 않습니다.
- ProgramSynthesisGateway: 컴파일, 의미 검증, Catalog 승인을 수행합니다.
- ProgramRuntime::reserve_synthesis: 예상 헤드 CAS로 미할당 컴파일 한 회를 차감합니다.
  체크포인트 식별성은 유지하면서 리스의 저널 헤드를 갱신합니다.
- ProgramRuntime::replace: 명시적인 인계/선행 실행 입력과 소스의 잔여 자원을
  사용하여 보유 중인 체크포인트와 승인된 대상을 소비합니다.
- reconnect/recover_child_synthesis: 기록된 세대/단계를 복구하거나
  대조·조정이 필요하다는 요구를 반환합니다.

이 이름은 C++ 호스트 API이며 JavaScript 명령이나 자동 모델 도구가 아닙니다.
시그니처와 전체 호출 방식은 실제 저장소 헤더/서비스 스키마를 사용하세요.
제너레이터 제어는 API의 Unmanaged 실행 보장을 유지합니다. 이 표기가 호스트
제어가 없다는 뜻은 아닙니다. 컴파일러 승인이 동작 품질을 입증하지는 않습니다.
