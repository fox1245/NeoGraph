# 実行時の子の合成と置換

**Languages:** [English](runtime-handoffs.md) | [한국어](runtime-handoffs.ko.md) | [日本語](runtime-handoffs.ja.md) | [简体中文](runtime-handoffs.zh-CN.md)

このリファレンスは、これらのサービスを実際に公開しているホスト向けです。スキルによって
ng.compile、ng.replace、想像上の MCP 置換ツールが API になることはありません。
互換 Harness MCP サーフェスはワークフローをコンパイルして開始します。実行中の置換には、
ここで説明するネイティブホスト統合が必要です。

## 必須のホストパケット

有効な owner/run/version、現在の系譜の先頭、利用可能なレジストリ、提案スキーマ
（テンプレートパラメーターまたは完全なソース）、入出力契約、残りの制限、結果／診断の形式を、
提供されたホストサービスから取得します。リクエストに含まれていなければ、利用可能な設定を
調べてください。バインディングを推測したり、操作が実行されたと主張したりせず、欠けている
契約を特定してください。

モデルが提案するのはソースまたはパラメーターです。ホストが権限を提供し、状態を原子的に
変更します。プロバイダーの認証情報と信頼済みの権限付与は、ホストが保持します。

## 子の作成

1. 具体的な子タスクと必要な出力に対して、ソースまたはテンプレートパラメーターを提案します。
   親に許可された能力と残りの制限だけを要求します。
2. 指定された境界で、ホストの提案エンベロープを送信します。ホストが実際の親／先頭を
   結び付け、リソースを予約し、コンパイルし、意味を検証し、受け入れ、公開して、子を
   バインドします。モデルが提供する権限付与は、権限として有効ではありません。
3. 結果を読みます。拒否された場合は、返された診断と残りの修正許容枠を使います。
   バインド済みの結果なら、正確な子バインディングと入力契約を使います。
4. 受け入れ済みの spawn コマンドを yield します。結果が必要なら await で包みます。
   子の結果または正確な失敗を記録してください。キューに入った提案を、実行された子として
   報告してはいけません。

例として、チャットボットのレビュー済み review テンプレートは、kind="review"、turn、source を
含むチェックポイントを emit します。そのホストは "review-" + turn から名前を導出し、
バインドする前にソースをレビュー済みテンプレートと照合します。これらのフィールド名は
その例に固有のもので、汎用の提案スキーマではありません。

## 現在の Harness の置換

1. 後継が必要とする情報を含む、明示的でシリアライズ可能な状態を構築します。
   会話／タスクの進捗と、保持した作業に再合流するために必要な正確な入力を含めます。
2. checkpoint(state, stableSite) を yield します。ホストがその境界でリースを保持します。
3. ホストが合成の意図を永続的に記録し、動的コンパイル一回分を予約し、後継を
   コンパイル／検証／受け入れしたうえで、世代 CAS により、置換対象としてその正確な
   バージョンを選択します。
4. 後継は新しいジェネレーターを開始します。新しい作業の前に、宣言された引き継ぎ状態を
   input.handoff から復元します。引き継ぎがある場合、カウンターや履歴をゼロから
   初期化してはいけません。ホストは previous_run_id もバインドします。
5. 論理的な親、子との関係、出力契約、付与された権限の互換性を維持します。
   補充できないリソースの残量は、後継に移転します。

境界を越えるのは JSON 状態であり、QuickJS のヒープ、ジェネレータースタック、ポインター、
Promise、ネイティブハンドルではありません。公開済みのグラフ／バージョンは不変です。

## 保持された子と回復

保持された子のバインディングと元の入力が、既存の作業を特定します。現在のネイティブ
ランタイムでは、継承したバインディングを記録された入力で spawn すると、その子に再合流します。
入力は元のテキストのキー順ではなく、正規化された JSON の内容で比較されます。その内容を
変更すると競合になります。新しいタスクには、ホストが新たに受け入れたバインディングと、
新たに予約され、権限・制限を縮小した子の予算が必要です。置換によって、完了済みの外部作業を
繰り返したり、すでに消費した制限枠を復元したりしてはいけません。

先頭が古いことによる競合では、アクティブな世代を再読み込みします。プロバイダーまたは
コンパイラーの結果が不確かな場合、提供されたホスト経路で照合する必要があります。
利用できる回答がないという理由だけで再ディスパッチしてはいけません。子から親への
キャンセルや全体のキャンセルを仮定せず、論理的なファミリーに対してホストが返した
キャンセル契約に従います。返された実行保証を正確に報告してください。

## ネイティブホスト実装のエントリーポイント

- RuntimeConfig::checkpoint_handler: ハンドル／リースをキューに入れ、速やかに戻ります。
  リースを保持すると世代が一時停止します。ホストの作業はスケジューラーの外で行います。
- ProgramRuntime::prepare_child_synthesis: 提案と、ホストが別途発行した認可の権限付与を、
  保持中の親チェックポイントに結び付けます。この権限付与によって、親の残りの
  コンパイル予算や実時間予算が補充されることはありません。
- ProgramSynthesisGateway: コンパイル、意味検証、Catalog での受け入れを行います。
- ProgramRuntime::reserve_synthesis: 期待する先頭に対する CAS で、未割り当てのコンパイル
  一回分を消費します。チェックポイントの識別情報を保持したまま、リースのジャーナル先頭を更新します。
- ProgramRuntime::replace: 保持中のチェックポイントと受け入れ済みターゲットを消費し、
  明示的な引き継ぎ／先行実行の入力と、置換元に残っているリソースを使います。
- reconnect/recover_child_synthesis: 記録された世代／段階を回復するか、必要な照合を返します。

これらの名前は C++ ホスト API であり、JavaScript コマンドでも自動的に使えるモデルツールでも
ありません。シグネチャと完全な呼び出し方法には、実際のリポジトリヘッダー／サービススキーマを
使ってください。ジェネレーター制御では、API の Unmanaged 実行保証が維持されます。
このラベルはホストの制御が存在しないという意味ではありません。コンパイラーが受け入れたことは、
動作の品質を証明しません。
