## 1. 目的と、固定された範囲

この手順書は、残っているQ0とQ7のリリースゲートを、順序付きの、フェイルクローズの手順にしたものです。アーキテクチャは変更**しません**。

- JavaScriptは、利用者が書くグラフと制御の、唯一の言語であり続けます。
- `GraphEngine` は、Coreとアプリケーションのノードの、唯一のエグゼキューターであり続けます。
- `ProgramRuntime` は、コマンドのadmission、永続的な効果、リプレイ、キャンセル、子のスケジューリングの、唯一の所有者であり続けます。
- strict CoreのJSONは、正規のデータであり続け、公開されるソース言語にはなりません。
- C++による直接の構築は、信頼された組み込み用のAPIであり続けます。公開のProgram JSONのオペレーション言語を残すための、互換性という口実にはなりません。

この手順は、issue #35（`trusted_direct`）にも、永続的なPromiseスケジューラーにも、着手しません。どちらも、機能を絞った永続プロファイルを完了するための前提条件ではなく、どちらも、従来形式の削除とまとめて行ってはいけません。

## 3. すべての手順に適用される規則

1. **範囲を黙って減らさない。** Windowsは、Q0の要件です。ローカルな `WIN32` の例外は、完了ではありません。この要件を外すには、別に承認されたアーキテクチャの変更が必要で、実装側の免除では済みません。
2. **ベンダーのソースを、意図せずに変えない。** QuickJSのリリース、archiveのダイジェスト、ライセンス、除外した `quickjs-libc.c`、非公開のシンボルの名前空間を、明示したままにします。プラットフォーム向けのシムやパッチは、実行時の意味を変えるため、ランタイムIDと来歴のエビデンスに入れなければなりません。
3. **切り替えのフェンスの後に、従来形式へのフォールバックを残さない。** JavaScriptのadmissionが失敗しても、JSON、Core DSL、古いオペレーションツリーのコンパイラーを選んではいけません。
4. **ファイル名だけで削除しない。** 残されているProgramの型には、正規のストレージや、信頼されたC++の基盤になっているものがあります。削除する前に、各依存を、legacy-only、shared-with-JavaScript、shared-with-trusted-C++のどれかに分類してください。
5. **ソースのチェックアウトを証明にしない。** 最終的なストレージの証明は、固定した完全なインベントリ、または正確なデプロイなしの証明から得ます。空のチェックアウトや、合成したCTestのフィクスチャから得てはいけません。
6. **どのフェーズもフェイルクローズにする。** 入口または出口の条件が満たされなければ、手順は止まります。厳格なゲートを警告に格下げすることも、従来形式のオーサリングを再び開くこともありません。

## 4. 完了までの手順（順序付き）

### M0 — リリースの境界を固定し、エビデンスの索引を作る

**入口：** 承認済みの親の契約と、この対になる仕様が存在すること。

1. 候補のコミットと、切り替えのIDを1つ選びます。
2. ソースツリーの外に、変更できないエビデンスの索引を記録します。索引は、コミット、コンパイラーとツールチェーン、CMakeのキャッシュとオプション、対象のプラットフォームとアーキテクチャ、QuickJSのリリース、archiveのダイジェスト、ビルドオプション、以下のすべてのコマンド、すべての結果ファイルのSHA-256のIDを、結び付けなければなりません。
3. 測定の前に、サポートするマトリクスを記録します。Linux x86_64とarm64、macOS、Windows x64です。それぞれ、親の契約が求める箇所では、Coreだけの構成と、QuickJSを有効にしたProgramの構成を、対象にしなければなりません。
4. 既存のデプロイなしの証明は、過去のエビデンスとしてのみ保存します。その2026-08-10のIDを、後の削除リリースの認証に使ってはいけません。

**出口：** 候補とエビデンスのスキーマが変更できない状態になり、エビデンスの索引にエントリがない限り、次のフェーズは、合格の結果を報告できないこと。

### M1 — QuickJSのポータビリティの実装を完了する

**入口：** M0に合格していること。

1. Windowsで `NEOGRAPH_BUILD_QUICKJS_CONTROL=ON` がビルドできるようにします。QuickJSをデフォルトで有効にしたり、`quickjs-libc.c`、`std`、`os`、動的なモジュールローダー、公開のQuickJSのエクスポートを追加したりしてはいけません。
2. タイミング、スタック上限、アロケーター、コンパイラーの互換性のための調整は、レビュー済みの、NeoGraph自身が持つ層に置きます。同梱のarchiveに、黙ってパッチを当ててはいけません。
3. `JavaScriptRuntimeIdentity` と来歴を拡張し、admission済みのバンドルが、上流のarchiveとビルドオプションに加えて、ポートやシムの正確な実装も特定できるようにします。このIDが異なる場合、リプレイは、ディスパッチの前に失敗しなければなりません。
4. `neograph_quickjs` は非公開のままにし、静的なCのシンボルに接頭辞を付けます。共有の `neograph::program` がそれらをエクスポートしないこと、静的なコンシューマーが、別にリンクされたQuickJSと衝突しないことを、検証します。
5. 最小限のC言語での組み込みのスモークテスト用の実行ファイルを追加します。これは、ランタイムとコンテキストを作成し、決定的なソースを評価し、明示的なC関数を1つバインドし、割り込みとメモリ／スタックの上限を強制し、`std` と `os` がないことを示さなければなりません。

**出口：** サポートする3つのOSのすべてで、きれいなディレクトリから、QuickJSを有効にした構成とCoreだけの構成の両方を、構成してビルドでき、新しいランタイムIDが記録されていること。

### M2 — ビルド、パッケージ、インストール済みコンシューマーのマトリクスを適格性確認する

**入口：** M1に合格していること。

以下の行ごとに、きれいなビルドディレクトリとインストールディレクトリを使います。ビルドツリーの中だけで成功しても、十分ではありません。

| プラットフォーム | 必須のQuickJS有効の行 | 必須のCoreだけの行 |
| --- | --- | --- |
| Linux x86_64 | Programの静的と共有。ランタイムとHarnessのテスト。Cのスモークテスト。インストール済みのコンシューマー | 静的と共有のインストール済みコンシューマー。QuickJSのリンク、インターフェース、エクスポートのエビデンスがないこと |
| Linux arm64 | Programの静的と共有。ランタイムとHarnessのテスト。Cのスモークテスト。インストール済みのコンシューマー | 静的と共有のインストール済みコンシューマー |
| macOS | Programの静的と共有。ランタイムとHarnessのテスト。Cのスモークテスト。インストール済みのコンシューマー | 静的と共有のインストール済みコンシューマー |
| Windows x64 | MSVCでのProgramの静的と共有。ランタイムとHarnessのテスト。Cのスモークテスト。インストール済みのコンシューマー | 静的と共有のインストール済みコンシューマー |

インストール済みのQuickJSコンシューマーは、構文の拒否だけでなく、インストール済みのパッケージを通じて、**成功する** `define()` と `function* main()` の公開と実行を、実際に行わなければなりません。また、既存の、独立してリンクした2つ目のQuickJSとの衝突プローブも、残す必要があります。インストール済みコンシューマーのドライバーは、`python scripts/verify_ci.py install --work-dir <fresh-output> --jobs 2 --program --quickjs` です（共有ライブラリには `--shared` を追加します）。非公開のシンボルの検査は、ELFとMach-Oだけが対象のままです。現在のWindowsのインストールの行では、`--quickjs` を付けません。この完了基準を満たすには、Windowsでの静的な名前空間付けと、共有ライブラリのエクスポートの隠蔽について、引き続き、ネイティブな検査のエビデンスが必要です。ネイティブのランタイムとC ABIのテストは、その代わりにはなりません。

**出口：** すべての行が、インストール先のプレフィックスから実行され、パッケージのメタデータ、ローダーとリンクのクロージャー、実行ファイルの出力、非公開のシンボルの検査結果が記録されていること。

### M3 — 隔離、リプレイ、ABI、破棄時の安全性を適格性確認する

**入口：** M2に合格していること。

1. 有効にしたすべてのプラットフォームで、QuickJSランタイムの隔離コーパス、JavaScriptとHarnessのエンドツーエンドのテスト、決定的なリプレイと復旧のテスト、障害注入のテスト、ネイティブABIの適合性を、実行します。
2. Linuxでは、QuickJSを有効にして、ASan+UBSanとTSanを実行する必要があります。macOSでは、QuickJSを有効にして、サポートされているASan／UBSan相当を実行する必要があります。Windowsでは、QuickJSを有効にして、サポートされているMSVCのAddressSanitizerの構成を実行する必要があります。使えないサニタイザーを、実行したことにしてはいけません。ツールチェーン固有の制約は、エビデンスの索引に記録してください。
3. テストコーパスには、長いJavaScriptの評価中のキャンセル、保留中の `callCore` での割り込み、アロケーターの破棄、キャンセル後のコールバックの完了、競合する2つ目のQuickJSエンジンを含めます。
4. ソース、ランタイム、プロファイル、ネイティブバインディングの不一致が、プロセスを再起動した後も含めて、ディスパッチの前に失敗することを、検証します。

**出口：** サポートするサニタイザーとランタイムの行がすべて、NeoGraphまたはQuickJSの所有権の欠陥を隠すsuppressionなしで通り、拒否されたフィクスチャのすべてで、ディスパッチが0回であることが確認されていること。

### M4 — 性能、起動、メモリ確保、バイナリサイズのゲートを閉じる

**入口：** M3に合格していること。

1. 既存の、Linuxでブロッキングとなるマトリクスを実行します。

   ```sh
   python scripts/verify_ci.py quickjs-performance --work-dir <fresh-build-root> --jobs 4
   ```

   新しい、まだ存在しない、自分が所有するビルドルートと、ソースのルートにある実際のGitチェックアウトを使います。変更していない `run_quickjs_performance.py` は、コミットとdirtyの来歴を要求するため、無関係なチェックアウトの下に展開したarchiveでは足りません。条件を合わせた、無効のビルドと有効のビルド、およびその結果は、そのルートの下に残ります。`<fresh-build-root>/quickjs-performance.json` を、非公開のエビデンスの索引に保存してください。

   承認済みの事前登録が、引き続き、しきい値の根拠です。不合格の候補に合わせて、しきい値を緩めてはいけません。
2. macOSとWindowsを測定する前に、起動、メモリ確保、有効にしただけで使わない場合とCoreだけの場合の測定について、バージョン管理された事前登録を追加します。1回の時間ではなく、繰り返したコールドとウォームの分布を記録します。
3. プラットフォームごとに、機械可読な適格性確認のレポートを作成します。インストール済みのCoreだけのバイナリとProgramのバイナリのサイズ、動的な依存のクロージャー、ランタイムの作成と起動のサンプル、アロケーターのハイウォーターマーク、正確なビルド構成を含めます。Coreだけの行には、QuickJSのオブジェクト、リンクの依存、エクスポートされたシンボル、メモリ確保の経路、QuickJSに起因するサイズの増加が、あってはなりません。
4. 失敗した、またはばらつきの大きい指標は、事前登録した方法で再実行するまで、不合格のゲートとして扱います。平均してリグレッションを打ち消してはいけません。異なるオプションの組み合わせを比較してもいけません。

**出口：** ブロッキングとなる性能、サイズ、起動、メモリ確保のしきい値がすべて通り、署名された結果のIDがエビデンスの索引にあること。

### M5 — 最終的なストレージのdrainを取り直し、削除の境界を棚卸しする

**入口：** M4に合格していること。従来形式の公開と再開が、告知されたフェンスの向こう側にあること。

1. プレリリースも本番のデプロイも、これまで一度も存在しなかった場合は、この切り替えのIDに対して、名前付きのデプロイなしの証明を、新しく取得します。そうでなければ、従来形式の書き込みをフェンスの向こう側に置き、永続的なProgramストアとHarnessストアすべての、整合した読み取り専用のスナップショットを取得します。
2. SQLiteでは、本物の整合したスナップショットを使い、使用中のWAL／SHM／ジャーナルのサイドカーファイルは拒否します。PostgreSQLでは、通常のカスタム形式の `pg_dump` を取得します。`PGDATA` をマウントしたり、稼働中のデータベースを監査したりしてはいけません。
3. すべてのストアと、検出されたすべての従来形式のアーティファクトを、列挙します。それぞれを、`translated`、`drain_only`、`rejected` のどれかに分類します。`drain_only`、アクティブまたは復旧可能な実行、結果が不明なもの、アクティブな従来形式のアクティベーション、スキャンされていない参照は、いずれも、絶対的な阻害要因です。
4. 削除の直前に、実際の最終的な証明を実行します。

   ```sh
   python3 scripts/audit_legacy_drain.py \
     --inventory <inventory.json> \
     --root <frozen-export-root> \
     --output <evidence-root>/legacy-drain-proof.json \
     --require-final
   ```

5. 別に、ソースの依存のインベントリを作成します。従来形式に見えるすべての型、ファイル、テスト、スキーマに、`legacy_only`、`shared_with_javascript`、`shared_with_trusted_cpp` のラベルを付け、その置き換え先、または残す理由と、リグレッションテストを挙げます。名前から推測してはいけません。

**出口：** 監査ツールが `final_drain.passed_is_true` を報告し、その証明とソースの依存のインベントリが、同じ切り替えのIDに結び付いており、従来形式の書き込みのフェンスが、リリースまで有効なままであること。

### M6 — 共有している依存を置き換えてから、従来形式のオーサリングとランタイムのコードを削除する

**入口：** M5に合格していること。

1. まず、残されている、信頼されたC++の呼び出し箇所を、Program-documentのJSONと、`ProgramPlan` のオペレーションツリーのディスパッチャーから、移行します。信頼されたAPIが、プロセス内で正規のデータを構築するのはかまいません。ただし、利用者が書く2つ目の制御言語を、公開したり、永続化したりしてはいけません。
2. 従来形式への依存を断ち切る間も、JavaScriptのコマンドの経路は保ちます。置き換え後も、`ProgramRuntime` のadmission、予算、ジャーナルと効果、キャンセル、リプレイの不変条件が、同じように保たれなければなりません。古い経路を削除する前に、その動作に関するリグレッションテストを追加します。
3. 次のものを、エイリアスもパーサーのフォールバックも残さずに削除します。
   - Program-documentのv1〜v4のスキーマと、その公開されたソースの経路
   - 保存済みのアーティファクトが必要としなくなった後の、従来形式の `CanonicalJson` のソースのデコード
   - 従来形式の `ProgramPlan` のオペレーションツリーのパース、ローワリング、ディスパッチ
   - HarnessのProgram-JSONの変換と、従来形式専用のサンプル、テスト、ドキュメント
   - 互換性のためのビルドとリンクの依存、および残されているランタイム選択のコード
4. 残すのは、依存のインベントリが、正規のストレージ、または必須の信頼されたC++の組み込み基盤と印を付けたアーティファクトだけです。特に、JavaScriptのソース、バンドル、ジャーナルの形式や、HarnessのJavaScriptトランスレーターを、`program` 名前空間を共有しているというだけで削除してはいけません。
5. drainの監査ツールと変更できない証明は、役に立つなら、リリースのエビデンスとして残してかまいません。ただし、デプロイ可能な従来形式のランタイムへのフォールバックを、残してはいけません。

**出口：** 新規のものも保存済みのものも、どの実行経路も、Program JSONのオペレーションツリーを、パース、コンパイル、ディスパッチ、またはフォールバックできないこと。公開のオーサリングの境界が公開するのは、JavaScriptと、信頼されたC++の組み込みだけであること。

### M7 — 最終的なクリーンルームでの検証と、リリースの記録

**入口：** M6に合格していること。

1. 削除の後、新しいディレクトリから、M2〜M4を繰り返します。インストール済みコンシューマーとサニタイザーのビルドも含みます。互換性のあるチェックアウトの結果を、再利用してはいけません。
2. 最終的なツリーに対して、グラフの同等性、ストレージのマイグレーション、決定的なリプレイ、クラッシュと障害、ネイティブABI、JavaScriptとHarnessのスモークの各スイートを、実行します。
3. スナップショットの後の変更によって、従来形式の状態がadmissionされたり、再開されたり、変更されたりした可能性がある場合は、M5をやり直します。そうでなければ、検証済みの証明のIDを、リリースのエビデンスの索引に保存します。
4. `completion_state.legacy_runtime_removal` を更新するのは、すべてのエビデンスが受理された後に限ります。そのうえで、アーキテクチャ、マイグレーション計画、公開の境界、変更履歴（changelog）、サンプル、issueの状態を、同じリリースの変更の中で更新します。
5. エビデンスの索引は、リリースとともに公開します。ロールバックは、以前にadmissionされたJavaScriptのリリースやアクティベーションを選ぶか、互換性のあるバイナリを復元することで行います。Core DSLやProgram JSONのオーサリングを再び開くことはありません。

**出口：** Q0とQ7のゲートが完了していること。利用者が書く言語は1つ、正規のCore IRは1つ、Programの永続性と効果のモデルは1つで、従来形式の実装へのフォールバックは残っていません。

## 5. 削除の棚卸し：必要な区別

次の現在の領域は、M5の間に、明示的に分類する必要があります。これは出発点となるチェックリストであり、すべてを無条件に削除してよいという許可ではありません。

| 領域 | 名前だけでは削除できない理由 |
| --- | --- |
| `include/neograph/program/plan.h`、`src/program/plan.cpp`、`compiler.cpp` と `run_attempt.cpp` の従来形式の部分 | Program JSONのオペレーションツリーを実装しており、削除の候補です。ただし、呼び出し側が先に、従来形式でない、信頼されたC++またはJavaScriptの経路へ移る必要があります。 |
| `SourceKind::CanonicalJson`、`ProgramSource::parse`、バンドル／カタログ／マイグレーションの互換性のための分岐 | 残されている従来形式の状態をデコードします。M5で、それを必要とする状態がないことが証明された後でなければ、削除できません。 |
| `schemas/program-document-v1.schema.json` から `v4` まで | 従来形式のオーサリング用のスキーマで、公開された経路とともに消えるべきものです。 |
| `program-source`、`program-bundle`、`program-version`、command-journal、strict Coreの各形式 | JavaScriptや信頼されたC++が必要とする、正規のストレージになりうるもので、個別に残すかどうかを判断する必要があります。 |
| `authoring.h`、JavaScriptのソースとコマンドのコード、Harnessのトランスレーター | 最終的なJavaScriptの境界を担っているため、残す必要があります。 |
| `tests/integration/find_package_program/main.cpp` | 現在は、Program documentを持つC++ビルダーを使っています。削除する前に、最終的な、信頼されたC++またはJavaScriptの経路へ移行してください。 |
| `scripts/audit_legacy_drain.py` | エビデンス用のツールであり、ランタイムのフォールバックではありません。残すかアーカイブするかを、意図して決めてください。 |

## 6. 完了の記録

フェーズが完了するのは、そのエビデンスが変更できない索引に追加され、出口の条件を通過し、次のフェーズの入口の条件が満たされている場合だけです。単体テストのスイートが通っていても、プラットフォーム、インストール済みコンシューマー、性能、最終的なdrainのゲートの代わりにはなりません。
