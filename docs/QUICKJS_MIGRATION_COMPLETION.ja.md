# QuickJS移行完了ランブック

**Languages:** [English](QUICKJS_MIGRATION_COMPLETION.md) | [한국어](QUICKJS_MIGRATION_COMPLETION.ko.md) | [日本語](QUICKJS_MIGRATION_COMPLETION.ja.md) | [简体中文](QUICKJS_MIGRATION_COMPLETION.zh-CN.md)

**ステータス:** 提案中のリリース完了手順。残っているゲートがすべて通過したという証拠ではありません。

**日付:** 2026-08-11

権限: [QuickJS Control Architecture](QUICKJS_CONTROL_ARCHITECTURE.md)、[QuickJS Control Runtime Migration Plan](QUICKJS_CONTROL_MIGRATION.md)、およびオーナーローカルな実行可能ランタイム契約。

## 1. 目的と固定されたスコープ

このランブックは、残りのQ0およびQ7リリースゲートを、順序付けられたフェイルクローズ手順に変換するものである。アーキテクチャは変更**しない**。

- JavaScript は、ユーザーによって書かれたグラフ/制御言語としては、唯一のものである。
- `GraphEngine` は唯一のCore/アプリケーションノード実行基盤として残る；
- `ProgramRuntime` はコマンドのadmission、永続的な効果、リプレイ、キャンセル、および子スケジューリングの唯一の所有者として残る；
- Strict Core JSON は正規データであり続け、公開ソース言語ではありません。
- 直接のC++構築は、公的なProgram JSON操作言語の互換性の言い訳ではなく、信頼された埋め込みAPIとして残る。

この手順は issue #35（`trusted_direct`）や永続的なPromise スケジューラを開始するものではない。どちらも制限付き永続プロファイルを完了するための前提条件ではなく、どちらもレガシー環境関連の除去にバンドルしてはならない。

## 3. すべてのステップに適用されるルール

1. **無言のスコープ縮小はしない。** WindowsはQ0要件である。ローカルの`WIN32`例外は完了ではない。その要件の削除には、実装側の放棄ではなく、個別に承認されたアーキテクチャ変更が必要である。
2. **意図しないベンダーソース流用なし。** QuickJSリリース、アーカイブダイジェスト、ライセンス、除外された`quickjs-libc.c`、非公開シンボル名前空間を明示的に維持する。プラットフォームシムやパッチは実行可能セマンティクスを変更し、ランタイムアイデンティティと来歴証拠に含まれなければならない。
3. **カットオーバー境界後のレガシーフォールバックなし。** 失敗したJavaScript admissionがJSON、Core DSL、旧Operationsツリーコンパイラを選択してはならない。
4. **ファイル名ベースの削除なし。** 一部の保持されるProgramタイプは企業標準ストレージまたは信頼されるC++インフラである。各依存をレガシー専用、JavaScriptと共有、または信頼されるC++と共有に分類してから削除すること。
5. **ソースチェックアウトの証明なし。** 最終的なストレージ証明は、フリーズされた完全な在庫リストまたは正確なノーデプロイメント宣誓書から得られるものであり、空のチェックアウトまたは合成CTestフィクスチャからは決して得ならない。
6. **すべてのフェーズはフェイルクローズである。** エントリ/終了条件の失敗はシーケンスを停止させる。ハードゲートを警告にダウングレードしたり、レガシーオーサリングを再開したりしない。

## 4. 順序立った完了手順

### M0 — リリース境界を凍結し、証拠索引を作成する

**入口:** 承認された親契約と本仕様書が存在すること。

1. 候補コミットを1つとカットオーバーIDを選択する。
2. ソースツリー外に不変の証拠インデックスを記録する。これは、コミット、コンパイラ/ツールチェーン、CMakeキャッシュ/オプション、ターゲットプラットフォーム/アーキテクチャ、QuickJSリリース/アーカイブダイジェスト/ビルドオプション、以下のすべてのコマンド、およびすべての結果ファイルのSHA-256による識別子を結び付ける必要がある。
3. 測定前にサポート対象マトリクスを記録する: Linux x86_64およびarm64、macOS、Windows x64。それぞれが、親契約で要求されるCore専用とQuickJS対応Programの両方をカバーしなければならない。
4. 既存の非デプロイ証明は、歴史的証拠としてのみ保存する。その2026-08-10の識別子を使用して、それ以降の削除リリースを認証してはならない。

**出口:** 候補と証拠スキーマは不変であり、証拠インデックスのエントリがなければ、次のフェーズは合格結果を報告してはならない。

### M1 — QuickJSポータビリティ実装を完了する

**入口:** M0は合格。

1. `NEOGRAPH_BUILD_QUICKJS_CONTROL=ON`をWindows上で、QuickJSをデフォルトで有効にせず、`quickjs-libc.c`、`std`、`os`、動的モジュールローダー、または公開QuickJSエクスポートを追加せずにビルド可能にする。
2. タイミング、スタック制限、アロケータ、またはコンパイラ互換性の適応のすべてを、レビュー済みのNeoGraph所有レイヤーに配置する。ベンダー提供のアーカイブを密かにパッチしないこと。
3. `JavaScriptRuntimeIdentity`/provenanceを拡張し、承認済みバンドルが正確なポート/shim実装に加えて、上流アーカイブとビルドオプションを識別できるようにする。この識別情報が異なる場合、リプレイはディスパッチ前に失敗しなければならない。
4. `neograph_quickjs`をプライベートに保ち、その静的Cシンボルにプレフィックスを付ける。共有の`neograph::program`がこれらをエクスポートしないことを検証し、静的コンシューマが別途リンクされたQuickJSと衝突しないことを検証する。
5. 最小限のC組み込みスモーク実行可能ファイルを追加する。ランタイム/コンテキストを作成し、決定論的ソースを評価し、明示的なC関数を1つバインドし、割り込み、メモリ/スタック上限を強制し、`std`/`os`が存在しないことを証明する必要がある。

**出口:** 3つのサポート対象オペレーティングシステムのすべてが、新しいランタイムIDを記録して、クリーンなディレクトリからQuickJS有効とCore-onlyの両方の構成を設定、ビルドできる。

### M2 — ビルド、パッケージ、インストール済みコンシューママトリクスを検証する

**エントリー:** M1は合格。

以下の各行について、クリーンなビルドディレクトリとインストールディレクトリを使用してください。ビルドツリー内のみの成功では不十分です。

| プラットフォーム | QuickJS必須行 | Core限定必須行 |
| --- | --- | --- |
| Linux x86_64 | Program 静的 + 共有; runtime/Harnessテスト; C スモーク; インストール済みコンシューマ | 静的 + 共有インストール済みコンシューマ; QuickJSリンク/インターフェース/エクスポートの証拠なし |
| Linux arm64 | Program 静的 + 共有; runtime/Harnessテスト; C スモーク; インストール済みコンシューマ | 静的 + 共有インストール済みコンシューマ |
| macOS | Program 静的 + 共有; runtime/Harnessテスト; C スモーク; インストール済みコンシューマ | 静的 + 共有インストール済みコンシューマ |
| Windows x64 | Program 静的 + 共有（MSVC）; runtime/Harnessテスト; C スモーク; インストール済みコンシューマ | 静的 + 共有インストール済みコンシューマ |

インストールされたQuickJSコンシューマは、単なる構文拒否ではなく、インストール済みパッケージを通じた**成功する**`define()`および`function* main()`の公開/実行を実行しなければならない。また、既存の独立してリンクされた2番目のQuickJS衝突プローブも維持しなければならない。Windowsが静的シンボル名前空間と共有エクスポートの隠蔽をネイティブ検査ツールで検証し、チェックをスキップしないように、`scripts/test_find_package.sh`を拡張する（または同等のプラットフォーム対応ドライバに置き換える）。

**終了:** すべての行はインストール済みプレフィックスから実行され、パッケージメタデータ、ローダー/リンカークロージャ、実行可能出力、およびプライベートシンボル検査結果を記録します。

### M3 — 分離、リプレイ、ABI、およびティアダウンの安全性

**開始条件:** M2が合格した。

1. 有効化されたすべてのプラットフォーム上で、QuickJSランタイム分離コーパス、JavaScript/Harnessエンドツーエンドテスト、決定論的リプレイ/リカバリテスト、フォールトインジェクションテスト、およびネイティブABI適合性を実行する。
2. Linuxは、QuickJS有効のASan+UBSanおよびTSanを実行しなければならない。macOSは、QuickJS有効のサポートされるASan/UBSan相当を実行しなければならない。Windowsは、QuickJS有効のサポートされるMSVC AddressSanitizer構成を実行しなければならない。利用不可能なサニタイザーを実行したと主張してはならず、ツールチェーン固有の制限をエビデンス索引に記録する。
3. 長時間のJavaScript評価中のキャンセル、保留中の`callCore`での割り込み、アロケーターのティアダウン、キャンセル後のコールバック完了、および競合する2つ目のQuickJSエンジンをテストコーパスに含める。
4. 送信前、およびプロセス再起動後を含めて、ソース/ランタイム/プロファイル/ネイティブバインディングの不一致がフェイルクローズすることを検証する。

**終了:** すべてのサポートされるサニタイザー/ランタイム行は、NeoGraphまたはQuickJSの所有者障害を隠すサプレッションなしで合格する。すべての拒否されたフィクスチャは、ディスパッチのゼロを確認する。

### M4 — パフォーマンス、起動、割り当て、バイナリサイズのゲートを完了する

**開始条件:** M3が合格した。

1. 既存のLinuxブロッキング行列を実行する:

   ```sh
   scripts/build_quickjs_performance_matrix.sh \
     <fresh-build-root> <evidence-root>/quickjs-performance-linux.json
   ```

その受け入れ済み事前登録がしきい値の権限であり続ける。失敗した候補への対応としてしきい値を緩めないこと。
2. macOSおよびWindowsを測定する前に、それらの起動、割り当て、および有効だが未使用/Core専用の測定値について、バージョン管理された事前登録を追加する。個別のタイミングではなく、低(暖)分布の繰り返しを記録する。
3. 各プラットフォームについて、インストール済みCore専用およびProgramのバイナリサイズ、動的依存関係クローズ、ランタイム作成/起動サンプル、アロケーターの高水になるマーク、正確なビルド構成を含む、機械可読な認定レポートを作成する。Core専用行には、QuickJSに起因するQuickJSオブジェクト、リンク依存関係、エクスポートされたシンボル、割り当てパス、サイズ増加がまったくあってはならない。
4. 失敗したメトリックまたはノイジ、LSメトリックは、プリ登録された方法で再実行されるまで失敗したゲートとして扱う。回帰を取り除くために平均化したり、異なるオプションセットを比較したりしてはならない。

**終了:** 各ブロッキングのパフォーマンス/サイズ/起動/割り当てのしきい値が合格し、その署名付き結果の同一性がエビデンスインデックスに存在する。

### M5 — 最終ストレージドレインを再確立し、削除境界を棚卸しする

**開始:** M4が合格済み。レガシーの公開/再開は、発表済みのフェンスの背後にある。

1. プレリリースまたは本番デプロイが一度も存在したことがなければ、このカットオーバーIDに対して、新規の名前指定なしデプロイ未実施の証明を取得する。それ以外の場合は、レガシー書き込みをフェンスの背後に置き、すべての永続的なProgramストアとHarnessストアの一貫性のある読み取り専用スナップショットを取得する。
2. SQLiteでは、実際の一貫性のあるスナップショットを使用し、ライブのWAL/SHM/journalサイドカーを拒否する。PostgreSQLでは、通常のカスタム形式の`pg_dump`を取得する。`PGDATA`をマウントしたり、ライブデータベースを監査したりしては決してならない。
3. すべてのストアと、発見されたすべてのレガシーアーティファクトを列挙する。それぞれを`translated`、`drain_only`、または`rejected`として分類する。`drain_only`、アクティブ/リカバリ可能な実行、不明な結果、アクティブなレガシーアクティベーション、および未走査の参照は、ハードブロッカーである。
4. 実際の最終証明を、削除の直前に実行する:

   ```sh
   python3 scripts/audit_legacy_drain.py \
     --inventory <inventory.json> \
     --root <frozen-export-root> \
     --output <evidence-root>/legacy-drain-proof.json \
     --require-final
   ```

5. ソース依存関係のインベントリを別途作成する。レガシーに見える型/ファイル/テスト/スキーマごとに、`legacy_only`、`shared_with_javascript`、または`shared_with_trusted_cpp`のラベルを付け、その置換または保持理由の名前を付け、回帰テストの名前を付ける。名前からこれを推測してはならない。

**終了:** 監査人は`final_drain.passed_is_true`を報告する;証明とソース依存関係インベントリは両方とも同じカットオーバーIDにバインドされており、レガシー書き込みフェンシングはリリースまでアクティブのままです。

### M6 — 共有依存を置換してから、レガシーのオーサリング/ランタイムコードを削除する

**開始条件:** M5が通過した。

1. 最初に、保持されている信頼できるC++呼び出し元を、Program-document JSONと`ProgramPlan`の操作ツリーのディスパッチャから移行する。信頼できるAPIはプロセス内で正規のデータを構築できるが、2つ目のユーザーが作成した制御言語を公開または永続化してはならない。
2. レガシー依存を切断しつつ、JavaScriptコマンドパスを保持する。置換は同じ`ProgramRuntime`のadmission、バジェット、ジャーナル/効果、キャンセル、およびリプレイの不変条件を維持しなければならない。その行動の回帰テストを、旧パスを削除する前に追加する。
3. エイリアスやパーサーのフォールバックなしに削除する:
   - Program-document v1–v4スキーマとその公開ソースルート。
   - 保存されたアーティファクトがそれを要求しなくなった場合のレガシー`CanonicalJson`ソースデコード。
   - レガシー`ProgramPlan`オペレーションツリーのパース、lowering、およびディスパッチ。
   - Harness Program-JSON 翻訳とレガシーのみの例/テスト/ドキュメントである。
   - 互換性のあるビルド/リンク依存関係と保持されたランタイム選択コード。
4. 依存関係インベントリが正規ストレージまたは必要な信頼できる C++ 埋め込みインフラストラクチャとしてマークする成果物のみを保持してください。特に、`program` ネームスペースを共有するからといって、JavaScript ソース/バンドル/ジャーナル形式や Harness JavaScript translator を削除しないでください。
5. ドレイン監査ツールと不変の証明をリリース証拠として有用であれば保持してください。ただし、デプロイ可能なレガシーランタイムフォールバックを保持してはなりません。

**終了:** 新しいまたは保存された実行パスは、Program JSON操作ツリーを解析、コンパイル、ディスパッチ、またはフォールバックできません。パブリックな作成境界は、JavaScriptと信頼されたC++埋め込みのみを公開します。

### M7 — 最終クリーンルーム検証およびリリース記録

**開始条件:** M6 が合格しました。

1. M2–M4を、削除後の新しいディレクトリから繰り返します。インストール済みコンシューマーとサニタイザービルドを含みます。互換性チェックアウトからの結果は再利用できません。
2. 最終ツリーに対して、グラフ等価性、ストレージ移行、決定的リプレイ、クラッシュ/障害、ネイティブABI、JavaScript/Harnessスモークスイートを実行する。
3. スナップショット後の変更がレガシー状態を許可、再開、または変更した可能性がある場合は、M5 を再実行してください。それ以外の場合は、検証済みの証明のアイデンティティをリリース証拠インデックスに保存してください。
4. `completion_state.legacy_runtime_removal` は、すべての証拠が承認された後にのみ更新してください。その後、同じリリース変更でアーキテクチャ、移行計画、公開境界、チェンジログ、例、および課題状態を更新してください。
5. 証拠インデックスをリリースとともに公開してください。ロールバックは、以前にadmissionされた JavaScript リリース/アクティベーションを選択するか、互換のあるバイナリを復元します。Core DSL や Program JSON のオーサリングを再開してはなりません。

**終了条件:** Q0 と Q7 のゲートが完了している: ユーザー作成言語が1つ、正規の Core IR が1つ、Program の耐久性/効果モデルが1つ、そしてレガシー実装フォールバックが残っていないこと。

## 5. 削除インベントリ: 必要な区別

以下の現在の領域は、M5中に明示的な分類が必要です。これは出発点のチェックリストであり、それらすべてを無差別に削除する許可ではありません。

| 領域 | 名前だけで削除できない理由 |
| --- | --- |
| `include/neograph/program/plan.h`、`src/program/plan.cpp`、`compiler.cpp` および `run_attempt.cpp` のレガシー部分 | これらは Program JSON 操作ツリーを実装しており、削除候補であるが、呼び出し側はまず非レガシーの trusted C++ またはJavaScript パスに移行する必要がある。 |
| `SourceKind::CanonicalJson`、`ProgramSource::parse`、bundle/catalog/migration 200互換ブランチ | これらは、保持されたレガシー状態をデコードします。M5 がそれらを必要とする状態がないことを証明した後にのみ削除してよい。 |
| `schemas/program-document-v1.schema.json` から `v4` まで | それらは legacy のオーサリングスキーマであり、パブリックルートとともに消えるべきである。 |
| `program-source`、`program-bundle`、`program-version`、コマンドジャーナル、および厳格な Core フォーマット | これらは JavaScript または信頼された C++ が必要とする正規のストレージであり、個別の保持決定が必要です。 |
| `authoring.h`、JavaScript ソース/コマンドコード、Harness トランスレータ | それらは最終的な JavaScript 境界を保有し、保持されなければならない。 |
| `tests/integration/find_package_program/main.cpp` | それは現在、Programドキュメントを保持するC++ builderを実行しています。削除前に、最終的な信頼済みC++またはJavaScriptパスに移行してください。 |
| `scripts/audit_legacy_drain.py` | これはエビデンスツールであり、ランタイムフォールバックではありません。意図的に保持またはアーカイブしてください。 |

## 6. 完了レコード

フェーズは、その証拠が不変インデックスに追加され、終了条件が満たされ、次のフェーズの開始条件が真である場合にのみ完了します。グリーンのユニットスイートは、プラットフォーム、インストール済みコンシューマー、パフォーマンス、または最終ドレインゲートを置き換えることはできません。
