# Pythonクライアントのオーバーヘッド：現在のランナーと過去の結果

**Languages:** [English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [简体中文](README.zh-CN.md)

このディレクトリでは、NeoGraphのPythonバインディングとPython SDKのクライアントを、ローカルのインプロセスのプロトコルpeerに対して比較します。測定する実時間には、クライアントの処理、サーバーのスケジューリング、HTTPのやり取りが含まれます。サーバー側のコストが一定だと確認されているわけではありません。ここでは、実際のモデルは動かしません。表に載せているのは、2026-04-29にx86_64のUbuntu 24.04（WSL2）、Python 3.12.3で測定した結果です。更新後のSDKへの切り替えを測ったものではありません。

## 過去の逐次実行のオーバーヘッド：K=1

`bench_a2a_clients.py` で、ローカルの定型のA2Aレスポンスを使った結果です。記録上の中央値の比は1.93倍でした。

| クライアント（2026-04-29） | 中央値 | P95 | スループット |
|---|---:|---:|---:|
| `neograph_engine.a2a.A2AClient` | 1,137 µs | 1,381 µs | 860 req/s |
| `a2a-sdk` 1.0.2 | 2,196 µs | 2,746 µs | 444 req/s |

`bench_openai_clients.py` で、ローカルの定型のChatレスポンスを使った結果です。記録上の中央値の比は1.54倍でした。NeoGraphのプロバイダーの旧ラベルを残しているのは、古い実装を区別するためです。現在のインポート対象という意味ではありません。

| クライアント（2026-04-29、旧プロバイダー） | 中央値 | P95 | スループット |
|---|---:|---:|---:|
| `neograph_engine.llm.OpenAIProvider`（削除済み） | 1,252 µs | 1,423 µs | 789 req/s |
| `openai` 2.33 | 1,927 µs | 2,393 µs | 509 req/s |

## 過去の並行スループット

`bench_concurrent.py` で、ローカルのA2A peerに対し、K ∈ {1, 4, 16, 64}、1行あたり500リクエストを送った結果です。

| K（2026-04-29、A2A） | NeoGraph req/s | a2a-sdk req/s | 比 |
|----:|---------------:|--------------:|--------:|
| 1 | 881 | 448 | 1.97× |
| 4 | 1,461 | 446 | 3.28× |
| 16 | 403 | 390 | 1.03× |
| 64 | 343 | 275 | 1.25× |

K=16と64でスループットが落ちたのは、`ThreadingHTTPServer` とクライアントが相互に影響した結果を含んでいます。標準ライブラリの上限を切り出したものでも、asyncio一般の制約を示したものでもありません。K=4の結果から、ほぼ線形にスケールすると言えるわけでもありません。これは、サンプリングした1つの構成の結果です。

## 現在のAPIと依存関係

現在のOpenAIの比較では、許可済みのHTTP Chatのディスクリプターとランタイムのオプションから `SchemaProvider` を作り、`make_provider_request` と `invoke` を使います。本物の型付きの所有された結果を受け取り、失敗か完了か、表示用のテキストを確認します。`OpenAIProvider`、`CompletionParams`、`complete()` は削除済みのAPIです。リクエストのモデルは明示的に指定します。コントロールには、指定しない限り、型付きファクトリーのデフォルトを使います。これは、旧プロバイダーのコンストラクターのデフォルトではありません。

どちらのクライアントも、同じプライベートなHTTPのループバックのpeerと、同じChatのルートを使います。レスポンスは、テキストが `ok` の定型のものです。peerは、ルート、モデル、プロンプトを検証します。ホスト型の認証情報も、カスタムCAも、有料の呼び出しも不要です。これはHTTP/1.0のローカルなプロトコルのワークロードです。TLSやHTTP/2のトランスポートの適格性確認でも、ネイティブのリプレイのベンチマークでもありません。定型のトークン使用量は、プロバイダーが報告した値として用意したフィクスチャのデータです。測定したトークン数でも、予算の課金でもありません。

現在のソースに合ったwheelを、[Pythonバインディングガイド](../../docs/python-binding.md)に従ってインストールし、そのあと、下の比較用のSDKをインストールします。ソースからビルドする場合は、Coreだけでも外部の `SchemaProvider::runtime` が必要です。[ビルドガイド](../../README.md)に従ってください。Pythonのラッパーだけでは、古いwheelに型付きのネイティブAPIを追加することはできません。
NeoGraph `0.14.2` では、wheelとネイティブのコンシューマーを、alpha SDK `0.3.3`（インターフェースのリビジョンと共有世代は6）に合わせる必要があります。

## 新しいコホートの実行

リポジトリのルートから実行します。wheel、ソース、SDKのリビジョン、Pythonのビルド（GILのモードを含む）、比較対象のパッケージのバージョン、プラットフォーム、peerのプロトコル、ウォームアップ、反復回数、失敗を記録してください。ランナーのデフォルトは500リクエストで、測定の前にウォームアップします。並行実行のランナーは、K=1/4/16/64を順に実行します。

```bash
# First install a wheel matching this source via docs/python-binding.md.
python -m pip install a2a-sdk openai httpx
python benchmarks/python_clients/bench_a2a_clients.py 500
python benchmarks/python_clients/bench_openai_clients.py 500
python benchmarks/python_clients/bench_concurrent.py 500
```

古い表は、新しい出力とは別に保管してください。レイヤーごとの比を掛け合わせても、OpenAIをA2Aの中で使ったときのエンドツーエンドの高速化にはなりません。そのような組み合わせのワークロードは、ここでは測定していません。現在の実装について、クライアントが一般に2〜3倍速いという保証も、±5%で再現できるという主張もありません。
